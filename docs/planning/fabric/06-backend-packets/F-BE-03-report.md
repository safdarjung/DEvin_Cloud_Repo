Schema summary (ADR D36): `CanvasSpecSchema = { version: 1, root: id, nodes: CanvasNode[1..24] }`, strict. `CanvasNode` = discriminated union on `kind`:
- 7 D31 blocks, reused via `XBlockSchema.safeExtend({ id })` (keeps their refinements); callout also takes `action?`.
- `layout` { variant grid|stack|tabs|split, children: id[1..12], cols? 1–4, tabTitles? ≤80 chars }.
- `widget` = nested union on `name` (kpi|trend|list|timeline|approvals|staffAvailability|timetable|aiInsight|quickActions). `props` are serializable, strict mirrors of the existing widgets. Icons use a closed set of 24 kebab-case lucide names. Every href must be an internal `/path` (blocks `javascript:`, `//host`, and `https:`).
- `flow` { nodes[1..80] {id,label,type,x?,y?}, edges[≤160] {source,target,label?} }.
- `action?` = { type navigate|openSheet|setFilter|runScenario|installModule|approve|export, payload: record ≤10 keys, values ≤200 } on kpi, list rows and callout.
- Strings are ≤500 everywhere, lists are flat, nothing recurses. superRefine checks: unique ids, root and every layout child resolve, no layout cycle (DFS), root is a layout or a block.
Renderer: `CanvasRenderer({spec, onAction})` is the one dispatch point. It has no "use client" and no hooks, so it can render on the server. Blocks go to BlockRenderer, widgets to `WIDGETS` in the registry, layouts to grid/stack/split or shadcn Tabs. `flow` renders `<div data-flow-placeholder>` with the comment `// F-BE-20 wires FlowCanvas here`. An actionable kpi or callout is wrapped in a `<button>` that calls `onAction`; the kpi href is then dropped so a link never sits inside a button. Lists with actionable rows use a small inline row list, because ListWidget only supports links. No dangerouslySetInnerHTML.

Limitations: the timeline gets `now = new Date()` at render, so relative times can differ between server and client on hydration. Flow edge ids are not checked against flow node ids; F-BE-20 decides. KPI has no honesty `badge` prop (it was a ReactNode); add `badge?: simulated|limited` if canvases show simulated data (rule 7).
Security / integration risks: none known. Actions are data only; the caller must authorize and execute them (rule 6). A `<button>` wrapping a Card is valid in practice but strictly allows only phrasing content.
