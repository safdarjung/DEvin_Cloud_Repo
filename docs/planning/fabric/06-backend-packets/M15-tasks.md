Rulings:
- **Sources are SQL, not registered queries.** A registered query reads through the request's cookie/bearer client under a live user's RLS. A job has no user (service role, plain node), so it cannot run one. A report source is an allowlisted **security invoker SQL function** called by `.rpc()` from both paths: the job (service-role client; the function's own `where institution_id = p_institution_id` is the only filter) and on-demand `report.export` (caller's client; RLS applies on top). One implementation per source, no TS twin. Closed allowlist:
  - `attendance.daily` → `public.report_attendance_daily(p_institution_id uuid, p_as_of timestamptz, p_day_offset int default 0)` returns `(date date, grade text, section text, session_status text, enrolled int, marked int, present_weighted numeric, denominator int, percentage numeric)`. Day `d = (p_as_of at time zone tz)::date + p_day_offset`. One row per class section of the academic year containing `d` (no year → zero rows): active enrolments; the daily session on `d` (`period_id is null`), `session_status` = its status or `not_marked`; weighted counts exactly like 0009 `app.term_attendance_percentage` (`settings.attendance.statuses` `counts_present` / `in_denominator`); `percentage = round(100 * present_weighted / nullif(denominator, 0), 2)`. Order grade, section. Permission `attendance.read`. Recipient roles ⊆ {owner, principal, admin}. Params `{ dayOffset: 0 | -1 }`, default 0.
  - `finance.defaulters` → `public.report_fee_defaulters(p_institution_id uuid, p_as_of timestamptz, p_min_days_overdue int default 0)` returns `(admission_no text, student text, grade text, section text, invoice_no text, due_on date, days_overdue int, outstanding text)`. Invoices `issued|part_paid` with `due_on <= d - p_min_days_overdue`; `outstanding = (total - paid_total)::text` (exact, lesson 8); grade/section from the student's active enrolment in the invoice's year (left join); order `due_on, admission_no`; `limit 20000`. Permission `finance.read`. Recipient roles ⊆ {owner, principal, admin, accountant}. Params `{ minDaysOverdue: int 0–365 }`, default 0.
  - `tz` everywhere = `coalesce(i.settings -> 'locale' ->> 'timezone', 'Asia/Kolkata')` (0008 precedent). Both functions `stable`, `search_path = ''`, qualified names, execute revoked from public/anon, granted to authenticated + service_role.
  - Adding a source later = one SQL function + the `source` check value + one `app.report_source_roles` case + one `REPORT_SOURCES` entry + its params schema.
- **Table `scheduled_reports`:** `id`, `institution_id → institutions`, `name` 1–80 (unique `scheduled_reports_institution_id_name_key (institution_id, name)`), `source` check in the allowlist, `params jsonb not null default '{}'` (check `jsonb_typeof(params) = 'object'` and `length(params::text) <= 1000`), `cron text` (≤ 100), `recipient_roles text[]` (cardinality 1–5), `status` `active|paused` default `active`, `next_run_at timestamptz null`, `created_by → profiles not null`, `created_at`/`updated_at` + `set_updated_at`. Partial index `(next_run_at) where status = 'active'`. No delete; pause instead (debt row).
- **Cron = a documented SQL subset parser.** Five fields `M H DOM MON DOW`, evaluated in the institution timezone. `M` one integer 0–59 and `H` one integer 0–23, so a schedule fires at most once per day. `DOM` 1–31, `MON` 1–12, `DOW` 0–6 (0 = Sunday): each `*` or a comma list of integers / ranges `a-b`. No steps, names, `?`, `L`, `#`, leading-zero M/H, or `7` for Sunday. DOM and DOW both restricted → rejected (avoids cron's OR rule). Grammar regex, same string in TS and SQL: `^([0-9]|[1-5][0-9]) ([0-9]|1[0-9]|2[0-3]) (\*|L) (\*|L) (\*|L)$` with `L` = `[0-9]{1,2}(-[0-9]{1,2})?(,[0-9]{1,2}(-[0-9]{1,2})?)*`. `app.cron_field_match(p_field text, p_value int) returns boolean` (immutable). `app.cron_next_fire(p_cron text, p_tz text, p_after timestamptz) returns timestamptz` (stable): grammar miss or DOM+DOW both restricted → null; walk local dates `(p_after at time zone p_tz)::date + 0..366`; the first date matching DOM/MON/DOW whose `(d + make_time(H, M, 0)) at time zone p_tz > p_after` wins; none → null (e.g. `0 8 31 2 *`). Postgres does the timezone math (DST-safe); TS never computes fire times. Examples: `0 20 * * *` nightly 20:00, `30 7 * * 1` Mondays 07:30, `0 8 1 * *` monthly, `0 18 * * 1-6` Mon–Sat.
- **Write guard** `app.scheduled_reports_before_write()`, BEFORE INSERT OR UPDATE, security definer, `search_path = ''`, execute revoked from public. Trusted = `service_role` JWT claim (`nullif` on claims) or `session_user = 'postgres'` (lesson 5). INSERT by a non-trusted caller: `created_by := app.current_user_id()`. UPDATE: `institution_id` or `created_by` change → `code:forbidden`. Always: `recipient_roles` distinct and `<@ app.report_source_roles(new.source)`, else `code:validation_failed`. `next_run_at`: on INSERT or a `cron`/`status` change (any caller) → `case when status = 'active' then app.cron_next_fire(cron, tz, now()) end`; active with a null result → `code:validation_failed` ("cron never fires"). Any other UPDATE by a non-trusted caller keeps `old.next_run_at` (users cannot force a run); trusted callers (the sweep) keep their own value. `app.report_source_roles(p_source text) returns text[]` is an immutable `case`; unknown → null.
- **RLS** (07 §2.2 `report.schedule`; lesson 7 initPlan): `scheduled_reports` SELECT, INSERT and UPDATE = `institution_id = any((select app.my_institution_ids(array['owner','principal','admin'])))` (INSERT/UPDATE `with check` the same: `institution_id` is the only caller-supplied FK, lesson 2; `created_by` is forced). No DELETE policy. Grants as 0069. `tests/security/rls-expectations.ts` entry (write = owner/principal/admin, no delete).
- **Report documents** (policies added, none recreated): `documents.entity_type` check + `report`; `documents.mime` check + `text/csv`; bucket `tenant-docs` `allowed_mime_types` + `text/csv` (`update storage.buckets`). `app.my_report_ids()` (setof uuid, stable definer, initPlan, execute to authenticated) = ids of schedules whose institution holds an active membership of the caller with `role = any(recipient_roles)`. Permissive SELECT `documents_select_report`: `entity_type = 'report' and entity_id = any((select app.my_report_ids()))`. Restrictive FOR ALL `documents_report_guard` to authenticated: `using (entity_type <> 'report' or entity_id = any((select app.my_report_ids()))) with check (entity_type <> 'report')`. Result: only the service role writes report documents, and their readers are exactly the recipient roles. Owner/admin read one only when listed. This is narrower than 0067's broad branch on purpose ("readable by principal only"). Storage reads compose through `tenant_docs_select` unchanged. `documents/schemas.ts` `ENTITY_TYPES`/`ALLOWED_MIMES` stay as they are (users never upload reports).
- **Scheduling = a sweep inside the runner, not self-chaining jobs.** MOD's runner drops a disabled module's job, so a chain of jobs would die while the module is off. `public.enqueue_due_reports() returns int` (definer, `search_path = ''`, execute to service_role only): for up to 200 rows `status = 'active' and next_run_at <= now() and app.module_enabled(institution_id, 'scheduled_reports')`, locked `for update skip locked`: `app.enqueue_job(institution_id, 'report.generate', {scheduled_report_id, fire_at: next_run_at}, 'report.generate:<id>:<next_run_at UTC as YYYYMMDD"T"HH24MI"Z">')`, then `next_run_at = app.cron_next_fire(cron, tz, greatest(next_run_at, now()))`. Missed windows are skipped: at most one late run. The payload is built in SQL from the row (lesson 3). Module off → the row is untouched; when it is switched back on, the overdue window runs once. A job dropped by MOD's runner because the module went off after enqueue is lost (module off = feature off). `runOnceCore` calls the new port `enqueueDueReports()` once before it claims; a sweep error is logged with a correlation id and never blocks the claim loop. Granularity = runner cadence (hosted pg_cron every 5 min).
- **Handler `report.generate`** (plain node: relative `.ts` imports; `@/` only for types). Payload `{scheduled_report_id, fire_at}`. Re-read the schedule and its institution settings (lesson 11); missing or `paused` → return. Re-parse params with the source's Zod schema; failure → throw `invalid_params`. Rows via `runReportSource` on the service-role client with `asOf = fire_at`. CSV via `rowsToCsvText(rows, source.columns)` (header always present, formula cells escaped). More than 10 485 760 bytes → throw `report_too_large`. Upload to `tenant-docs` at `<institution_id>/report/<schedule_id>/<YYYYMMDDTHHMMZ>.csv` with `{ contentType: "text/csv", upsert: true }`. Insert the `documents` row (`entity_type 'report'`, `entity_id` = schedule id, `kind 'scheduled_report'`, `file_name '<name slug>-<local YYYY-MM-DD>.csv'` ≤ 200, `mime 'text/csv'`, `status 'active'`, `created_by` = schedule creator) with `onConflict: "path", ignoreDuplicates: true`, then read it back by path. Notify every active membership whose role is in `recipient_roles` at send time: `createNotification` type `report_ready`, `entityId` = document id, vars `{ report: name, date: local YYYY-MM-DD }`. Never log payloads or rows.
- **Idempotency per run window** (window = schedule × fire minute; at most one per day): job key above (unique `jobs.idempotency_key`; two concurrent sweeps → one job); deterministic storage path (`upsert`); unique `documents.path`; notification key `report_ready:<document_id>:<user_id>`. Retries and replays give one document and one notification per recipient.
- **Permissions** (T1): `report.schedule` = owner, principal, admin. `data.export` = owner, principal, admin, accountant. Append at each role's tail; Edit only (other lanes edit the same file).
- **Names** (all `module: "scheduled_reports"`): actions `report.schedule.save` {id?, name, source, params, cron, recipientRoles} (insert, or update by id) and `report.schedule.setStatus` {id, status}, both `report.schedule`. Job type `report.generate`: `JOB_MODULES` row `scheduled_reports`.
- **Notification template `report_ready`:** channels `["in_app"]` only, so no preference category or DB check change (in-app is never preference-filtered, 0068). Category `"report"` added to the `NotificationCategory` union only, not to `PREFERENCE_CATEGORIES`. - **ErrorCode map:** `unauthenticated` (no session) · `forbidden` (permission; module off via MOD; source permission on export; `42501`; trigger `code:forbidden`) · `not_found` (save/setStatus on an id the caller cannot see → 0 rows) · `validation_failed` (Zod: cron grammar, DOM+DOW, params, roles; trigger `code:validation_failed`: role not allowed for the source, cron never fires) · `conflict` (`23505` on `scheduled_reports_institution_id_name_key` → `fieldErrors.name`).
