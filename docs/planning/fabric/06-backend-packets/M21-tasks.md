Rulings:
- **No LLM in M21.** Zero gateway calls (`runStructured`/`streamAgent` untouched). Detection, model choice, numbers, intervals and confidence are deterministic TS. A narrative about a forecast is future work through M19 `insight.explain` on a forecast-derived insight; the LLM never writes or changes a forecast row. Evidence: every forecast row stores `evidence jsonb`, `confidence`, and `model` (the versioned algorithm name = detector_version; changing an algorithm means a new name `…_v2`, never new semantics under `_v1`). No `status`/`reviewer` columns: forecasts are read-only numbers, not actionable items.
- **No per-student forecasts — structural.** Exactly two kinds: `fee_collections_term` (institution-wide) and `attendance_rate_week` (school-wide or one class section). No `student_id` column anywhere. Series keys are closed: `fees:term`, `attendance:school`, `attendance:section:<class_section_id>`.
- **Series sources (SQL, security invoker, service-role only).**
  - `public.forecast_fee_series(p_institution_id uuid) returns table (term_id uuid, sequence int, name text, starts_on date, window_end date, collected_paise bigint, billed_paise bigint)` — every term of the institution ordered by `starts_on`. `window_end` (exclusive) = `lead(starts_on) over (order by starts_on)`, last term `ends_on + 1` (contiguous windows: vacation payments land in the preceding term). `collected_paise` = `round(sum(p.amount) * 100)::bigint` (coalesce 0) over payments of the institution with `(p.received_at at time zone tz)::date >= starts_on and < window_end` and **no** `payment_reversals` row for the payment (`not exists`, M12). `billed_paise` = same rounding over `invoices.total` with `term_id` = the term and `status <> 'cancelled'`. `tz = coalesce(i.settings -> 'locale' ->> 'timezone', 'Asia/Kolkata')`.
  - `public.forecast_attendance_series(p_institution_id uuid, p_from date, p_to date) returns table (class_section_id uuid, points jsonb)` — `p_to <= p_from` or `p_to - p_from > 400` → `raise exception 'code:validation_failed'`. Daily sessions only (`s.period_id is null`), `s.status = 'submitted'`, `s.date >= p_from and s.date < p_to`, sessions and records both filtered on `institution_id = p_institution_id`. Weighting exactly like 0009 `app.term_attendance_percentage` (lateral over `settings.attendance.statuses`: `present` += `counts_present` where `in_denominator`, `denominator` += 1 where `in_denominator`). Week = `date_trunc('week', s.date)::date` (ISO Monday). One row per section (`points` = `jsonb_agg({week_start, present, denominator} order by week_start)`) plus **one row with `class_section_id` null** = school-wide (Σ present, Σ denominator per week across sections). Weeks with denominator 0 omitted. ≤ sections + 1 rows (stays under PostgREST `max_rows = 1000`, M16 lesson).
  - Both `language sql stable security invoker set search_path = ''`, qualified names; `revoke execute … from public, anon, authenticated`; `grant execute … to service_role`. Only the job calls them (RLS bypassed by the service role; the explicit `institution_id` filters are the scope).
- **Series building (pure TS, `as_of` = the job's local run date `YYYY-MM-DD`).**
  - Fees: complete periods = rows with `window_end <= as_of`, value `collected_paise`, label = term `name`, `seasonKey = "t<sequence>"`. Targets = the next ≤ 3 rows after the last complete one (current term first). No complete period or no target → no forecast. `k = 2`.
  - Attendance: `monday0` = ISO Monday of `as_of`; RPC window `p_from = monday0 − 392 days`, `p_to = monday0`. Periods = points with `denominator > 0`, value `round2(100 × present / denominator)`, label `YYYY-Www` (ISO week), `seasonKey = "w<ISO week number>"`. Targets = weeks starting `monday0`, `+7`, `+14` (h = 1 is the current week). Stale series (no period with `week_start >= monday0 − 28 days`) → skipped entirely (vacations, last year's sections). `k = 4`.
- **Engine (pure TS, `src/modules/forecasts/engine.ts`).** `HOLDOUT = 3`. Models in tie-break order `["moving_average_v1", "seasonal_naive_v1"]`.
  - `moving_average_v1`: prediction for every target = mean of the last `k` values of the training periods; null when fewer than `k`. Flat over horizons.
  - `seasonal_naive_v1`: prediction for a target = value of the **latest** training period with the same `seasonKey` (scan from the end); null when none. (Fees: same term sequence last year; attendance: same ISO week last year. With few terms per year this naturally reaches back further.)
  - Backtest (single origin): needs `periods.length >= HOLDOUT + 1`. `train` = all but the last 3 complete periods; predict the 3 held-out periods from `train` only. A model with any null prediction, or whose held-out actuals are all 0, has no backtest. `MAPE` = mean over held-out pairs with `actual ≠ 0` of `|actual − predicted| / |actual|`, rounded to 4 dp (fraction, may exceed 1).
  - Selection: a model is eligible when it has a backtest **and** predicts every target from all complete periods. Lowest MAPE wins; ties → earlier in the model list. No eligible model or no target → no forecast (backtests still written).
  - Point/interval per horizon `h`: `hw = point × mape × √h`; `lower = max(0, point − hw)`, `upper = point + hw`; unit `pct` caps point and upper at 100. Rounding: `paise` → integer (`Math.round`), `pct` → 2 dp. `confidence = round3(clamp(1 − mape, 0, 1))`.
- **Tables (0094).** Both: `id`, `institution_id → institutions`, `series_key text`, `kind text` check in the two kinds, `class_section_id uuid null → class_sections`, `unit text` check `paise|pct`, `model text` check in the two models, `as_of date`, `created_at`/`updated_at` + `app.set_updated_at()`. Shape check on both: `(kind = 'fee_collections_term' and series_key = 'fees:term' and class_section_id is null and unit = 'paise') or (kind = 'attendance_rate_week' and unit = 'pct' and ((class_section_id is null and series_key = 'attendance:school') or (class_section_id is not null and series_key = 'attendance:section:' || class_section_id::text)))`.
  - `forecast_backtests` + `origin_start date`, `n_train int >= 1`, `holdout jsonb` (`jsonb_array_length = 3`; items `{start, label, actual, predicted}`), `mape numeric(8,4) >= 0`, `params jsonb` (`{k}` or `{match: "seasonKey"}`). Unique `(institution_id, series_key, model)`; unique `(id, institution_id, series_key, model)` (FK target).
  - `forecasts` + `backtest_id uuid not null`, composite FK `(backtest_id, institution_id, series_key, model) → forecast_backtests (id, institution_id, series_key, model) on delete cascade` (= "a backtest row exists before a forecast is shown", same series and model), `horizon int` 1–3, `period_start date`, `period_label text` 1–40, `point`/`lower`/`upper numeric(16,2)` with `0 <= lower <= point <= upper` and `unit <> 'pct' or upper <= 100`, `confidence numeric(4,3)` 0–1, `evidence jsonb` (`jsonb_typeof = 'object'`, `length(evidence::text) <= 4000`). Unique `(institution_id, series_key, horizon)`. Evidence = `{ history: [{start, label, value, billed?}] (last ≤ 6 complete periods, oldest first; billed paise for fees only), origin: {start, label}, params }`.
- **Latest run only (replace semantics).** The job upserts backtests on `(institution_id, series_key, model)` and forecasts on `(institution_id, series_key, horizon)` — one upsert call per table — then deletes the institution's forecasts and backtests with `as_of < payload.as_of` (forecasts first). Stale series, dropped horizons and ineligible models vanish. A job whose `as_of` is older than the institution's `max(as_of)` returns without writing (late replay). No audit row (system job; logs `job.id` + counts only).
- **RLS (07 §2.2 `forecast.read`; lessons 1/7).** Same SELECT policy on both tables, to authenticated: `(kind = 'fee_collections_term' and institution_id = any((select app.my_institution_ids(app.finance_roles()))))` or `(kind = 'attendance_rate_week' and institution_id = any((select app.my_institution_ids(array['owner','principal','admin','exam_controller']))))` or `(kind = 'attendance_rate_week' and class_section_id = any((select app.my_taught_section_ids())))` (mirrors `attendance_sessions_select`, 0020). Teachers therefore see their taught sections only — never school-wide or fees; accountants fees only; guardians, students, admissions nothing. **No INSERT/UPDATE/DELETE policy** (service role writes only, lesson 3). Table grants as 0069. `tests/security/rls-expectations.ts` entries.
- **Scheduling = runner sweep (M15 pattern).** `public.enqueue_due_forecasts(p_now timestamptz default now()) returns void` — `security definer`, `search_path = ''`; for every institution with `app.module_enabled(id, 'forecasts')` **and** something to forecast (`exists` a submitted attendance session with `date >= d - 400` or a payment with `received_at >= p_now - interval '400 days'` — keeps empty tenants, and most test fixtures, out of the queue): `d = (p_now at time zone tz)::date`, `perform app.enqueue_job(id, 'forecast.run', jsonb_build_object('as_of', d), 'forecast.run:' || id || ':' || to_char(d, 'YYYYMMDD'))` (payload built in SQL, lesson 3; once per local day via the unique key). Revoke from public, anon, authenticated; grant service_role. `07 §4` definer row. Runner port `enqueueDueForecasts()` is called in `runOnceCore` right after `enqueueDueReports()`; its error is logged with a correlation id and never blocks claiming. `JOB_MODULES["forecast.run"] = "forecasts"` (MOD runner drops it when the module is off).
- **Permissions.** `forecast.read` = owner, principal, admin, accountant, exam_controller, teacher (RLS scopes the rows). No write permission and no action: nothing user-callable writes forecasts.
- **Queries** (all `module: "forecasts"`, permission `forecast.read`, caller's client — RLS is the only row filter):
  - `forecasts.cards` `{}` → `ForecastCard[]`: horizon-1 rows of `attendance:school` then `fees:term` (whichever RLS returns). `metric` `"Attendance Rate"` / `"Fee Collection"` (fixture strings); `current` = last `evidence.history` value; `forecast` = `point`; `unit`; `confidence`; `direction`: `current = 0` → `forecast > 0 ? "up" : "flat"`, else `|forecast − current| / current <= 0.02` → `"flat"`, else up/down. No admissions card (out of scope).
  - `forecasts.financeSeries` `{}` → `FinanceForecastPoint[]`: no `fees:term` forecast visible → `[]` (no backtest → nothing shown). History points from the horizon-1 row's `evidence.history`: `month = start.slice(0, 7)`, `collected_paise = value`, `expected_paise = billed`, `forecast_low_paise = forecast_high_paise = value`. Then one point per horizon: `month = period_start.slice(0, 7)`, `collected_paise = 0`, `expected_paise = point`, low/high = `lower`/`upper`. `month` carries the term's start month (debt: CONTRACT rename to `period` in Workstream D).
  - `forecasts.list` `{kind?, classSectionId?}` → `ForecastRow[]` = `{ seriesKey, kind, classSectionId: string | null, sectionLabel: string | null, unit, model, horizon, periodStart, periodLabel, point, lower, upper, confidence, mape, nTrain, holdout: { start, label, actual, predicted }[], asOf }` (backtest embedded via `backtest_id`; label `${grades.code}-${class_sections.name}` like `timetable/queries.ts`). Order: kind, school-wide first, section label, horizon. This is where the backtested MAPE is shown.
