Source: owner directive 2026-11-02 (extension milestone X07, owner-approved; new plug-and-play module). Migration `0090` (claimed in `10-backlog-index.md` §3 — `20261028000090_visitors.sql`). No new deps. **Requires MOD merged** (hence M13, whose files the READ lines mirror; `src/lib/modules/catalog.ts`, `module` required on every definition, `app.module_catalog`/`app.module_enabled` from 0084, `JOB_MODULES`, `allModulesOn()` in seed + `createTestInstitution`). Module key `visitors` (category Operations, default **off**, no `requires`). New owning module `src/modules/visitors` (owns `visitor_entries`, `gate_passes`, `pickup_persons`). Builds on people (`students`, `guardians`, `guardian_students`), academics (`enrolments`, `class_sections.class_teacher_id`), notifications (`createNotification`, templates), jobs (`app.enqueue_job`, `JOB_REGISTRY`). Replaces fixtures: none. No UI (Workstream D).

Rulings:
- **Module.** Catalog entry `visitors: { label: "Visitors & gate pass", category: "Operations", description: "Front-desk visitor log, student early-leave gate passes and guardian-maintained pickup lists.", default: false }`, placed after `calendar`. Every X07 action/query declares `module: "visitors"`; job type `notify.gate_pass` gets a `JOB_MODULES` row `visitors`. Demo tenant and test institutions get it on through `allModulesOn()` (no seed/helper edit). SQL mirror: 0090 inserts `visitors` into `app.module_catalog` (`default_enabled = false`) via `insert into app.module_catalog (key, default_enabled) values ('visitors', false) on conflict (key) do update set default_enabled = excluded.default_enabled`. `app.module_enabled` (MOD, 0084) is defined once and is never redefined here. The drift test (`tests/db/module-enabled-sql.test.ts`) is red between T1 and T2 → controller commits T1 + T2 together. Exactly one "module disabled → forbidden" test (T10).
- **Permissions** (add to `permissions.ts` + 07 §2.2): `visitor.manage` = owner, principal, admin (front desk = admin role; visitor check-in/out/list, retention purge). `gatepass.manage` = owner, principal, admin ✓; teacher `s` = students actively enrolled in sections where they are class teacher (create, approve/reject, cancel, mark exit, list). `pickup.manage` = owner, principal, admin ✓ (on behalf of a guardian with no portal account); guardian `s` = own children (add/remove). Read query `visitors.pickupList` uses existing `student.read` (RLS scopes, transport.forStudent precedent). No other role gets anything.
- **Tables** (all: `institution_id`, `created_at`/`updated_at` + `app.set_updated_at()`, RLS on, every user-supplied FK bound to the row's institution in `with check`, table-qualified — lesson 2; initPlan helpers only — lesson 7; fixed constraint names so actions map `23505`):
  - `visitor_entries`: full_name 1–80; phone `^[6-9][0-9]{9}$`; purpose 1–120; host_staff_id → staff null; meeting_with 1–80 null; check (host_staff_id is not null or meeting_with is not null); id_type null in (aadhaar, driving_licence, voter_id, pan, passport, other); id_last4 null check `^[0-9A-Z]{4}$`; check ((id_type is null) = (id_last4 is null)); checked_in_at timestamptz default now(); checked_in_by → profiles not null; checked_out_at null; checked_out_by → profiles null; check (checked_out_at is null or checked_out_at >= checked_in_at). Index (institution_id, checked_in_at desc). **No full ID number column anywhere.**
  - `pickup_persons`: student_id → students; full_name 1–80; relation in (father, mother, grandparent, uncle, aunt, sibling, driver, other); phone `^[6-9][0-9]{9}$`; created_by → profiles. `pickup_persons_student_phone_key` unique (student_id, phone). No update (remove + add). No photo.
  - `gate_passes`: student_id → students; reason 1–200; guardian_id → guardians null; pickup_person_id → pickup_persons null **on delete set null**; collector_name 1–80, collector_relation text (snapshots, server-filled); status pending|approved|rejected|cancelled|exited default pending; requested_by → profiles; requested_at default now(); decided_by → profiles null, decided_at null; exited_at null, exit_marked_by → profiles null. `gate_passes_one_open_key` unique (student_id) where status in (pending, approved). Index (institution_id, requested_at desc). No delete. No phone stored.
- **Helpers** (definer, `search_path=''`, qualified, revoke public, grant authenticated — lesson 4; mirror `app.my_taught_student_ids` 0035 / `app.my_student_ids` 0020): `app.my_class_teacher_student_ids()` setof uuid = students with an `active` enrolment in a section from `app.my_class_teacher_section_ids()`, joins on the row's own institution — **X07 (0090) owns this helper.** M20 (0093) reuses it and never redefines it. `app.my_guardian_student_ids()` setof uuid = the guardian branch of `app.my_student_ids()` only (a student user never gets write scope).
- **RLS (07 §2.2, lesson 1).** M = `institution_id = any((select app.my_institution_ids(array['owner','principal','admin'])))`.
  - visitor_entries: SELECT/UPDATE M. INSERT M with `checked_in_by = (select app.current_user_id())`, checked_out_* null, host staff bound. DELETE M **and** `checked_in_at < now() - interval '180 days'` (retention purge only).
  - pickup_persons: SELECT M, or `student_id = any((select app.my_class_teacher_student_ids()))`, or `student_id = any((select app.my_guardian_student_ids()))`. INSERT/DELETE M or the guardian branch; INSERT also `created_by = current user` and student bound to institution. No UPDATE policy.
  - gate_passes: SELECT/INSERT/UPDATE M or `student_id = any((select app.my_class_teacher_student_ids()))`; INSERT student bound. No DELETE. Guardians/students: none (they get the notification).
- **Triggers / state machines** (lesson 3 — direct PostgREST writes obey the same rules; bypass only `nullif(current_setting('request.jwt.claims', true),'')::jsonb->>'role' = 'service_role'` or `session_user = 'postgres'` — lesson 5; the seed and `app.demo_reset`'s FK-nulling sweep rely on it).
  - `app.guard_visitor_entries` (invoker) BEFORE INSERT OR UPDATE: insert stamps checked_in_at = now(); update allows only checked_out_at null → set (stamps checked_out_at = now(), checked_out_by = current user); already out or any other column change → `code:invalid_state`.
  - `app.gate_pass_before_insert` (**definer** — reads guardian_students/guardians/pickup_persons without RLS recursion, DBT-45): exactly one of guardian_id / pickup_person_id, else `code:validation_failed`; guardian must have a `guardian_students` row for new.student_id in the same institution, pickup person's student_id must equal new.student_id and same institution, else `code:validation_failed` detail `collector is not authorised for this student`; sets collector_name/collector_relation from that row (guardian: `guardians.full_name` + `guardian_students.relationship`). Non-trusted writers additionally get status = pending, requested_by = current user, requested_at = now(), decided_*/exited_* null (client values overwritten).
  - `app.guard_gate_passes_update` (invoker) BEFORE UPDATE: allowed moves pending→approved|rejected|cancelled, approved→cancelled|exited; rejected/cancelled/exited terminal; anything else `code:invalid_state`. Immutable: institution_id, student_id, guardian_id, reason, collector_*, requested_*; pickup_person_id may change **only to null** with no status change (the FK set-null cascade — guardian removes a person used by a past pass). Stamps decided_by/decided_at on approved|rejected|cancelled, exited_at/exit_marked_by on exited.
  - `app.enqueue_gate_pass_notice` (**definer**) AFTER UPDATE OF status when old pending → new approved: `app.enqueue_job(new.institution_id, 'notify.gate_pass', jsonb_build_object('gate_pass_id', new.id), 'gatepass:' || new.id)`. Payload ids only.
- **Notification.** Type `gate_pass_approved`, channels in_app + sms, category `attendance` (existing preference category), vars {student, class, collector, time, school}, en + hi. Handler `notify.gate_pass` re-reads the pass (lesson 11): sends only if status is approved or exited; recipient = primary guardian's active `guardian` membership (mirror `notify.attendance_absence`); sms contact = guardian phone; time = decided_at "HH:MM" in institution timezone. Approval only — no exit notification (skipped).
- **ErrorCode mapping (actions).** `23505` by name: `pickup_persons_student_phone_key` → `conflict` fieldErrors.phone; `gate_passes_one_open_key` → `conflict` fieldErrors.studentId "Student already has an open gate pass." `42501` → `forbidden`. `23503` → `not_found`. `23514` → `validation_failed`. Trigger `code:*` through `mapSqlError`. Update/delete hitting 0 rows → `not_found` (a teacher's out-of-scope pass is `not_found`, no existence leak). Module off → `forbidden` (MOD gate).
- **Audit.** Event name = action name; payload ids, status (from/to), counts only. Never visitor names, phones, purpose, ID data, reasons, or collector names (lesson 10).
- **DPDP retention (India).** Purpose: campus safety. `visitor_entries` kept 180 days from check-in (`VISITOR_RETENTION_DAYS = 180`, SQL literal `interval '180 days'` — keep in sync), then deleted by `visitors.purge` (manual, managers; RLS allows deleting only rows past retention). ID: type + last 4 characters only (masked-Aadhaar convention; Aadhaar Act s.29 — never collect/store the full number); no ID scans. `pickup_persons`: kept while the guardian keeps them; removal is a hard delete; past passes keep name + relation only. `gate_passes`: part of the student's school record, kept with the institution, no phone. Front desk reads `VISITOR_PRIVACY_NOTICE` aloud/posted ("Your name and phone are recorded for campus security and deleted after 180 days."). Queries return pickup phones masked (`******1234`). Automated purge and DSR export: skipped (debt).
- **Honesty.** Guardian SMS goes through the existing channel adapter → simulated + badge until MSG91 (D42). Visitor ID is not verified: UI shows `<LimitedBadge>` "ID not verified — type and last 4 digits only" (Workstream D). 03-feature-matrix new row `F-SVC-06` = limited.
- **India specifics.** Phones = `phoneIN` (`src/lib/schemas/common.ts`) / DB regex `^[6-9][0-9]{9}$`; ID types include Aadhaar, driving licence, voter ID, PAN, passport; relation list includes `driver` (school-van/auto drivers); times rendered in the institution timezone (Asia/Kolkata default); hi template.

Skipped (smallest version): UI pages/nav (Workstream D); pickup-person photo (needs a documents entity type + storage policy rewrite owned by M05/M09/M15 — debt); daily dismissal pickup log (verification = `visitors.pickupList` + gate pass exit); QR/printed visitor badge; ID scans or OCR; exit notification; gate pass auto-expiry (stale approved passes are cancelled by staff; one-open index forces it); guardian-initiated gate pass requests and guardian read of passes; visitor pre-registration, blacklist, photo; automated retention purge job; per-student pickup cap; teacher pickup-list edits.
