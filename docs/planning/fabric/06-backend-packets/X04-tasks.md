Rulings:
- **Module.** Every X04 definition declares `module: "fee_plans"`; job type `fee_plans.late_fees` gets a `JOB_MODULES` row. Catalog entry after `online_payments`: `fee_plans: { label: "Late fees & instalments", category: "Finance+", description: "Late-fee rules, instalment plans for term invoices, and Tally/CSV ledger export.", default: true, requires: ["finance_plus"] }`. The settings schema needs no edit (MOD's `modules` schema derives from `OPTIONAL_MODULE_KEYS`). Module off → X04 actions/queries `forbidden`, the sweep enqueues nothing, `apply_late_fees` returns zeros; data kept. **Existing instalment plans still shape defaulters and fee reminders while the module is off** (they are agreements with parents; switching the module off must not turn a family into a defaulter).
- **`app.module_catalog` insert.** 0087 inserts `fee_plans` (`default_enabled = true`) via `insert into app.module_catalog (key, default_enabled) values ('fee_plans', true) on conflict (key) do update set default_enabled = excluded.default_enabled`. `app.module_enabled` (MOD, 0084) is defined once and is never redefined here; it already ANDs the `requires` chain, so `finance_plus` is enforced without extra code. T1 and T2 land in one commit (the drift test is red between them).
- **Invoice charge (reuse, never a second write path).** A late fee reaches the invoice only via `app.add_invoice_charge(p_invoice_id, 'late_fee', <description>, <amount>) returns uuid` (X03 ruling "Finance charge": invoice `for update`, `invoice_lines` row, `subtotal`/`total` += amount, ledger Dr `fees_receivable` / Cr `fee_income`, memo `late_fee invoice <invoice_no>`, audit `finance.invoice.charge_added`). X03-T3 must be merged before T4 starts; X04 never creates or redefines this function (X03 owns it). No ledger account change: late fees credit `fee_income`; the Tally export separates them by head (below).
- **Principal.** `app.invoice_principal(p_invoice_id uuid) returns numeric` (`language sql stable`, `search_path = ''`, execute revoked from everyone; callers are definers) = Σ (`amount − concession_amount`) of the invoice's lines whose `head` is a fee-component head (`tuition`, `transport`, `annual_charges`, `admission`, `exam`, `lab_computer`, `activity`, `caution_deposit`). Charge lines (`late_fee`, `library_fine`, any later head) are never principal. **Payments allocate principal first, in instalment `seq` order, charges last** — derived, nothing stored.
- **Late-fee rule = one row per fee structure.** `late_fee_rules`: id, institution_id, `fee_structure_id` unique → fee_structures, `kind` in (`flat`, `per_day`), `amount` numeric(12,2) > 0 (flat: once per unit; per_day: per day), `grace_days` int 0–90 default 0, `cap` numeric(12,2) null, check `(kind = 'flat' and cap is null) or (kind = 'per_day' and cap is not null and cap >= amount)`, `is_active` boolean default true, `updated_by` → profiles, created_at/updated_at + `app.set_updated_at()`. No delete (deactivate). A per-day rule always has a cap: unbounded fines are refused (several state fee-regulation acts cap fines; the school stays responsible for its state's limit — docs say so).
- **Late-fee semantics.** A *unit* = the invoice when it has no plan (`unit_seq` 0, due = `invoices.due_on`) or each instalment (`unit_seq` = its `seq`, its `due_on`). A no-plan unit is unpaid while `paid_total < app.invoice_principal(id)`; instalment k is unpaid while `paid_total < Σ amount(1..k)`. `days_late = today − (due_on + grace_days)` (today in `settings.locale.timezone`, default `Asia/Kolkata`); charge only when `days_late ≥ 1` and the unit is unpaid. Target: flat → `amount`; per_day → `least(cap, amount × days_late)`. Charge = target − Σ `late_fee_charges.amount` for (invoice, unit_seq); insert only when > 0 (top-up: a missed night catches up, a rerun adds nothing). Cap is per unit. Skip invoices that are `paid`/`cancelled`, have `due_on` null, have no active rule on the student's structure for the invoice's year (`fee_assignments(student_id, academic_year_id)` → `late_fee_rules.fee_structure_id`), or whose fee assignment has an `ews_rte` concession (RTE Act §12 seats are free; never fined).
- **`late_fee_charges`** (immutable record + idempotency): id, institution_id, invoice_id → invoices, `unit_seq` int 0–12, `charge_date` date, `days_late` int ≥ 1, `amount` numeric(12,2) > 0, `rule_id` → late_fee_rules, `invoice_line_id` uuid not null unique → invoice_lines, created_at; unique `(invoice_id, unit_seq, charge_date)` (a same-day second top-up waits for the next night: skip on conflict); `app.block_mutation()` on update/delete (demo-reset bypass is built in). Line description: `Late fee` (unit 0) or `Late fee — instalment <n>`, plus ` (<days_late> days)` for per_day.
- **`public.apply_late_fees(p_institution_id uuid) returns jsonb {charges int, amount numeric}`** (definer, `search_path = ''`, `service_role` only): zeros when `app.module_enabled(p_institution_id, 'fee_plans')` is false; candidate invoices ordered by id, each locked `for update` before its units are evaluated (same lock order as `record_payment`, no deadlock); per charge: `app.add_invoice_charge` → `late_fee_charges` insert. No extra audit (each charge is audited by `add_invoice_charge`; the rows + ledger are the record).
- **Nightly application.** `public.enqueue_due_late_fees() returns int` (definer, `search_path = ''`, `service_role` only): for each institution with `app.module_enabled(id, 'fee_plans')` and ≥ 1 active rule → `app.enqueue_job(id, 'fee_plans.late_fees', jsonb_build_object('as_of', <today in its tz>), 'fee_plans.late_fees:<institution_id>:<as_of>')` (jobs' idempotency key is globally unique → one job per institution per local day). Runner port `RunnerPorts.enqueueDueLateFees(): Promise<number>` = `admin.rpc("enqueue_due_late_fees")`, called once per `runOnceCore` before claiming, in its own try/catch (mirror M15's `enqueueDueReports`; add the same shape if M15 is unmerged). "Nightly" = first runner tick after local midnight (hosted cadence 5 min). Handler `fee_plans.late_fees` → `admin.rpc("apply_late_fees", { p_institution_id: job.institution_id })`, throws on error (runner retries; the function is idempotent). No manual "apply now" action.
- **Instalment plans.** `invoice_instalments`: id, institution_id, invoice_id → invoices, `seq` int 1–12, `due_on` date, `amount` numeric(12,2) ≥ 1.00, `created_by` → profiles, created_at/updated_at + trigger; unique `(invoice_id, seq)`. Written only by `public.set_invoice_instalments(p_invoice_id uuid, p_parts jsonb) returns int` (definer, `authenticated`, inline role check like `enqueue_term_invoices`): invoice `for update`; caller not a member of the invoice's institution → `code:not_found`; member without `app.finance_write_roles()` → `code:forbidden`; status not `issued`/`part_paid` → `code:invalid_state`; any `late_fee_charges` row for the invoice → `code:invalid_state` (plan locked once fined); parts = 2–12 objects `{due_on, amount}`, due dates strictly increasing, first ≥ `invoices.due_on`, last ≤ the academic year's `ends_on`, each amount ≥ 1.00 with ≤ 2 decimals, Σ = `app.invoice_principal` exactly → else `code:validation_failed`. Effect: delete the invoice's rows, insert the new ones (seq = array position), audit `fee_plans.instalments.set` (invoice_id, parts, previous_parts). `invoices.due_on` never changes. Replace = call again (allowed until the first late fee); no "remove plan".
- **Per-part status is derived, never stored.** `public.invoice_instalment_status(p_institution_id uuid, p_term_id uuid default null, p_invoice_id uuid default null)` returns `table (invoice_id uuid, seq int, due_on date, amount numeric, paid_amount numeric, status text)`; `language sql stable security invoker set search_path = ''`; non-cancelled invoices only; `paid_amount = least(amount, greatest(0, paid_total − Σ earlier amounts))`; status precedence `paid` (paid_amount = amount) → `overdue` (remainder > 0 and due_on < today in the institution tz) → `part_paid` (paid_amount > 0) → `due`; order invoice_id, seq; execute to `authenticated`, `service_role`. RLS decides visibility.
- **Defaulters respect instalments.** `listDefaulters` (core `fees`) drops plan invoices with no `overdue` part; for kept plan invoices `dueOn` = earliest unpaid part's `due_on`; `DefaulterRow` gains `onPlan: boolean` (addition only). M12's `finance.fee_reminder` handler skips plan invoices with no `overdue` part (same RPC, service role). Unpaid charges alone (late fee, library fine) do not make a plan invoice a defaulter. M15's `report_fee_defaulters` is unchanged (debt row).
- **Ledger export (Tally + plain CSV).** `public.ledger_voucher_lines(p_institution_id uuid, p_from date, p_to date, p_receipts_only boolean default true)` `language sql stable security invoker` (ledger RLS = finance roles) returns `(entry_id uuid, entry_date date, voucher_type text, voucher_no text, charge_head text, account text, debit numeric, credit numeric, memo text, admission_no text)`. Voucher = lines grouped by `(entry_date, coalesce(payment_id, invoice_id), memo)`. Type: group with `payment_id` whose cash/bank line is a debit → `Receipt`; with `payment_id` and a cash/bank credit → `Payment` (M12 void/refund/bounce); no `payment_id` → `Journal`. `voucher_no`: Receipt/Payment = the payment's `receipts.receipt_no`; Journal with memo `invoice <no>` = `invoice_no`; other Journals (charges, memo `<head> invoice <no>`) = `<invoice_no>/<head>/<YYYYMMDD>` and `charge_head = <head>`. `p_receipts_only` → Receipt + Payment only. `admission_no` via invoice → student (null when RLS hides it). Order `entry_date, voucher_type, voucher_no, debit desc, entry_id`. Execute to `authenticated`. TS pages it with `.range()` (1,000/page, max_rows lesson) until a short page; > 20,000 lines → `validation_failed` "Narrow the date range."
  - Layout `tally` (TallyPrime multi-ledger voucher import shape, one CSV row per ledger line): keys exactly `Date` (`DD-MM-YYYY`), `Voucher Type`, `Voucher No`, `Ledger Name`, `Dr/Cr` (`Dr`|`Cr`), `Amount` (string, 2 decimals, no ₹ or commas, always positive), `Narration` (memo + ` · ` + admission_no when present). Ledger names: `cash` → `Cash`, `bank` → `Bank`, `fees_receivable` → `Fees Receivable`, `fee_income` → `Fee Income` (but `Late Fee Income` when `charge_head = 'late_fee'`), `concession_expense` → `Fee Concession`; overridable per call by flat optional params `cashLedger`, `bankLedger`, `receivableLedger`, `incomeLedger`, `lateFeeLedger`, `concessionLedger` (trim 1–100; GET-friendly; nothing stored). Cash-basis schools set `receivableLedger` to their income ledger and keep `include=receipts`.
  - Layout `plain`: keys `date` (ISO), `voucherType`, `voucherNo`, `account`, `ledgerName`, `debit`, `credit` (numbers, rupees via paise helpers), `narration`, `admissionNo`. CSV for both via the existing `?format=csv` (`toCsvResponse`). Range: `from ≤ to`, span ≤ 366 days.
  - Honesty (rule 7): the Tally layout is not validated against a live Tally install → `<LimitedBadge>` "Tally layout — check ledger names before import" when the UI lands; feature matrix `limited`. No GST lines (school fees are GST-exempt; out of scope).
- **RLS (07 §2.2, lessons 1/2/7).** `late_fee_rules`: SELECT `institution_id = any((select app.my_institution_ids(app.finance_roles())))`; INSERT/UPDATE with `app.finance_write_roles()` + FK binding (`exists (select 1 from public.fee_structures fs where fs.id = late_fee_rules.fee_structure_id and fs.institution_id = late_fee_rules.institution_id)`); no DELETE. `invoice_instalments`, `late_fee_charges`: SELECT finance roles OR `exists (select 1 from public.invoices i where i.id = <t>.invoice_id and i.institution_id = <t>.institution_id and i.student_id = any((select app.my_student_ids())))`; no write policies (definer/service-role only, lesson 3). Teachers, admissions etc. see nothing. `tests/security/rls-expectations.ts` entries for all 3.
